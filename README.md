# Just do it. 🍅📊📈

> **「測る・記録する・分析する」をシームレスに繋ぐ、Python × クラウド連携型のポモドーロ＆作業記録デスクトップアプリ**

`Just do it.` は、日々の集中力維持と作業の振り返りを効率化するために開発した Windows / macOS 対応のデスクトップアプリです。
ポモドーロ・テクニックによる時間管理、ローカルとクラウド（Googleスプレッドシート）への二重記録、Gmail での週次レポート、そしてグラフによる振り返りまでをワンストップで実現します。

## 🌟 主な機能

### 1. 集中タイマー
- **5分だけやる**：やる気が出ない時に「とりあえず取りかかる」ための短時間モード（メニューで唯一の強調ボタン）
- **25分やる**：標準的なポモドーロ
- **休憩タイマー**：作業記録後、自動で最長10分の休憩タイマーへ移行し、終了時は音で知らせてメニューへ戻る
- **ここで終える**：それまでの経過時間（1分単位で切り上げ）を記録してメニューへ戻る

### 2. 記録
- **すぐ入力できる記録画面**：タイマー終了時、ウィンドウが最前面に出て、ダイアログを挟まずそのまま作業内容を入力できる
- **手動記録**：タイマーを使わなかった作業も後から追加（入力チェック付き・Enterキー対応）
- **二重バックアップ**
  - ローカル：CSV へ自動追記（`utf-8-sig` で Excel でも文字化けしない）
  - クラウド：Google Apps Script (GAS) 経由で Googleスプレッドシートへ送信（バックグラウンド通信で UI が固まらない）

### 3. 📊 振り返り（ダッシュボード）
- 今日 / 直近7日 / 累計の作業時間サマリー
- 直近14日間の日別作業時間（棒グラフ）
- よくやったこと（作業内容別の上位5件）

### 4. 📧 週次レポート（メールアドレスを登録するだけ）
- 「設定」でメールアドレスを入力し、届いた確認コードを入れるだけで登録完了
- **毎週月曜 9時ごろ、先週の振り返りレポートが自動で届く**（アプリを開いていなくても、PC の電源が切れていても届く）
  - 総作業時間と前の週との差、記録回数、記録した日数、作業内容別の内訳
- オフライン中の記録は自動で再送。メール内のリンクやアプリからいつでも配信停止でき、停止するとサーバー上の記録も削除される

### 5. ☁️ 自分のスプレッドシートへの記録（上級者向け・任意）
- 自分でデプロイした GAS の WebアプリURL を登録すると、記録を自分の Googleスプレッドシートにも送信

## 💾 データの保存場所

| 実行方法 | 保存先 |
| --- | --- |
| Windows アプリ | `%APPDATA%\JustDoIt\` |
| macOS アプリ | `~/Library/Application Support/JustDoIt/` |
| ソースから実行 | `main.py` と同じフォルダ |

`log/work_log.csv`（作業ログ）と `config.json`（設定）が保存されます。保存先はアプリの「設定」画面でも確認できます。

週次レポートに登録すると、レポート作成のために作業記録（日時・作業内容・時間）が配信サービスにも送信されます。サーバー上の記録は35日で自動削除され、配信停止時にはすぐ削除されます。

## ☁️ 自分のスプレッドシート連携の設定（上級者向け・任意）

1. Googleスプレッドシートを新規作成し、**「拡張機能」→「Apps Script」** を開く
2. [`gas/code.js`](gas/code.js) の内容をエディタに貼り付けて保存
3. **「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」**、アクセスできるユーザーを「全員」にしてデプロイ
4. 発行された URL（`https://script.google.com/macros/s/.../exec`）をアプリの **「設定」** に貼り付けて保存
5. 週次レポートを使う場合は、Apps Script エディタで `createWeeklyTrigger` を1回実行（毎週月曜9時台に送信）

> ⚠️ GAS のコードを修正したら「デプロイを管理」→「新バージョン」で再デプロイしないと反映されません。
> ⚠️ WebアプリURL を知っている人は誰でも書き込めるため、URL は公開しないでください（環境変数 `JUSTDOIT_GAS_URL` でも指定できます）。

## 🛠️ 開発者向け

### 週次レポート配信サービスのデプロイ（開発者が1回だけ行う）
利用者がメールアドレスを登録するだけで済むよう、配信用の GAS を開発者が1つだけ用意します。

1. **配信サービス専用の Google アカウント**で、Googleスプレッドシートを新規作成し、**「拡張機能」→「Apps Script」** を開く
   - メールはこのアカウントから送られる（利用者に差出人アドレスが見える）ため、普段使いのアカウントは使わない
   - 複数アカウントに同時ログインしていると Apps Script が開けないことがあるので、シークレットウィンドウなどで専用アカウントだけにログインして作業する
2. [`gas/report_service/Code.js`](gas/report_service/Code.js) を貼り付ける。プロジェクトの設定で「appsscript.json をエディタで表示」をオンにし、[`appsscript.json`](gas/report_service/appsscript.json) の内容も貼り付ける（タイムゾーン: Asia/Tokyo）
3. **「デプロイ」→「新しいデプロイ」→「ウェブアプリ」**、次のユーザーとして実行「自分」、アクセスできるユーザー「全員」でデプロイ
4. エディタで `createWeeklyTrigger` を1回実行し、権限を承認する（毎週月曜 9時台に `sendWeeklyReports` が実行される）
5. 発行された URL を [`main.py`](main.py) の `REPORT_SERVICE_URL` に設定してビルドする（開発中は環境変数 `JUSTDOIT_REPORT_URL` でも指定可）

- 書き込みにはメール認証で発行した端末ごとのトークンが必要です（サーバーにはハッシュのみ保存）。URL が公開されても、他人の記録の読み書きはできません
- 確認コードの送信は、同じアドレスに対して1分に1回・6時間で5回までに制限し、レポート用の送信枠を残すようにしています
- 無料の Google アカウントでは、メール送信は1日100通程度までです。利用者が増えたら Google Workspace への切り替えや、外部のメール配信サービスへの移行を検討してください

### ソースから実行
```bash
pip install -r requirements.txt
python main.py
```

### テスト
```bash
python -m unittest discover -s tests -v
```

### アプリのビルド
```bash
pip install -r requirements-dev.txt
pyinstaller --noconfirm --windowed --name JustDoIt main.py
```
`dist/` に Windows なら `JustDoIt/JustDoIt.exe`、macOS なら `JustDoIt.app` が生成されます（各 OS 上でビルドする必要があります）。

`v1.0.0` のようなタグを push すると、GitHub Actions（[`.github/workflows/build.yml`](.github/workflows/build.yml)）がテスト → Windows / macOS 両方のビルド → Release への添付まで自動で行います。

```bash
git tag v1.0.0
```

```bash
git push origin v1.0.0
```

## 🧩 工夫した点・苦労した点

- **通知を見逃さない UI**：タイマー終了時に入力ウィンドウを最前面（`-topmost`）かつモーダル（`grab_set()`）で開き、作業内容の記録漏れを防止
- **画面遷移とタイマーの整合性**：`after()` の予約IDを保持し、画面を切り替えるたびにキャンセルすることで、裏でタイマーが動き続ける不具合を解消
- **通信で UI を止めない**：GAS への送信を別スレッド＋タイムアウト付きで行い、ネットワークが遅くてもアプリが固まらない
- **GAS 連携のハマりどころ**：`doGet` 未定義によるエラーや、コード修正後に再デプロイしないと古い版が動き続ける問題を調査・解決
- **利用者に設定させない週次レポート**：当初は利用者が自分で GAS をデプロイする必要があったため、開発者が共用の配信サービスを持つ設計に変更。メールアドレスと確認コードだけで登録でき、アプリを開かなくても毎週レポートが届くことで習慣化を後押しする。トークン認証、確認コードの送信回数制限、メールソフトのリンク先読みで勝手に停止されないための確認ボタン、送信できなかった記録の再送キューなど、公開サービスとして安全に運用できるようにした
- **配布を見据えた設計**：ビルド後のアプリ内には書き込めないため、OS 標準のユーザーデータフォルダに保存先を切り替え。秘密情報（GAS URL）はコードから分離
