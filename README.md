# Just do it. 🍅📊📈

> **「測る・記録する・分析する」をシームレスに繋ぐ、Python × クラウド連携型のポモドーロ＆作業記録デスクトップアプリ**

`Just do it.` は、日々の集中力維持と作業の振り返りを効率化するために開発した Windows / macOS 対応のデスクトップアプリです。
ポモドーロ・テクニックによる時間管理、作業記録、グラフによる振り返り、そしてメールで毎週届くレポートまでをワンストップで実現します。

## 📥 ダウンロード（Python 不要）

[Releases](../../releases) ページから OS に合ったファイルをダウンロードしてください。

| OS | ファイル | 起動方法 |

## 🌟 主な機能

### 1. 集中タイマー
- **5分だけやる**：やる気が出ない時に「とりあえず取りかかる」ための短時間モード（メニューで唯一の強調ボタン。Enter キーでも始められる）
- **○分やる**：標準的なポモドーロ（初期値25分。設定画面で15〜90分から選べる）
- **休憩タイマー**：タイマーを最後までやって記録すると、そのまま休憩タイマー（初期値10分）へ移行し、終わったらメニューへ戻る（途中で切り上げることもできる）
- **ここで終える**：それまでの経過時間（1分単位で切り上げ）を記録してメニューへ戻る
- **やめる**：右上の「← 戻る」で、記録せずにタイマーをやめる（押し間違えないよう「ここで終える」から離して置き、確認を挟む）
- **終わったときの知らせ方を選べる**：「音を鳴らす」「ウィンドウを前面に出す」「OS の通知を出す」を設定画面で組み合わせられる（「試しに知らせてみる」で確認できる）
- **残り時間がひと目でわかる**：残り時間を数字と円形の進捗リングで表示
- **うっかり閉じても安心**：タイマーや入力の途中でウィンドウを閉じようとすると、ここまでの時間を記録するか確認する

### 2. 記録
- **すぐ入力できる記録画面**：タイマー終了時、ダイアログを挟まずそのまま作業内容を入力できる
- **最近やったことから選べる**：入力欄の下に最近の作業内容が並び、押すだけで入力できる（入力の手間が減り、「制作」「製作」のような表記の揺れも防げる）
- **手動記録**：タイマーを使わなかった作業も後から追加（入力チェック付き・Enterキー対応）
- **記録一覧で直せる・消せる**：振り返り画面の「すべての記録を見る・直す」から、記録を新しい順に一覧表示し、選んで作業内容・時間の修正や削除ができる（週次レポートに登録していれば、配信サービス上の記録も同じように直る）
- **メニューに今日の合計**：「今日 50分 ・ 3日連続」のように、今日の作業時間と連続して記録した日数を表示
- **ローカルに保存**：CSV へ自動追記（`utf-8-sig` で Excel でも文字化けしない）。設定画面の「フォルダを開く」から保存先をすぐ開ける

### 3. 📊 振り返り（ダッシュボード）
- 「週 ｜ 月 ｜ 年」の切り替えで、直近7日・30日（日別）と直近12か月（月別）を棒グラフで表示（まだ記録がないときは、画面の中で「5分だけやってみる」を案内）
- その期間の合計時間・記録した日数と、累計の作業時間
- よくやったこと（その期間の作業内容別 上位5件）

### 4. 📧 週次レポート（メールアドレスを登録するだけ）
- 設定の「週次レポート」タブでメールアドレスを入力し、届いた確認コードを入れるだけで登録完了
- 登録後は「テストメールを送る」で、最初のレポートを待たずにその場で1通届けて確かめられる（1日3回まで）
- **好きな曜日・時刻（6〜23時）に、1週間の振り返りレポートが自動で届く**（アプリを開いていなくても、PC の電源が切れていても届く）
  - 届くタイミングは登録時に選べ、あとから設定画面でいつでも変更できる（初期値は月曜 9時ごろ）
  - 朝・昼に届く場合は前日まで、夕方（18時）以降に届く場合はその日までの7日間を集計（月曜 9時なら先週の月〜日、日曜 21時ならその週の月〜日）
  - グラフ入りの HTML メール：総作業時間と前の週との差、記録した日、一番がんばった日、曜日ごとの棒グラフ、作業内容別の割合バー
  - 画像を使わず表とインラインスタイルで描くので、Gmail やスマホでも崩れない
- オフライン中の記録は自動で再送。メール内のリンクやアプリからいつでも配信停止でき、停止するとサーバー上の記録も削除される

### 5. 🎨 表示・操作
- 角の丸いボタンと余白を整えた、シンプルなデザイン。メインメニューは「5分だけやる」「○分やる」と3つのリンクだけ
- **ライト / ダーク / デバイスに合わせる** を設定画面の「全般」タブで選べる（「デバイスに合わせる」は Windows・macOS のダークモード設定に追従。Windows ではタイトルバーも暗くなる）
- キーボードでも操作できる（メニューで Enter キーを押すと「5分だけやる」、各画面で Esc キーを押すと前の画面に戻る）

### 6. 🔔 新しいバージョンのお知らせ
- 起動時に GitHub の最新リリースを確かめ、新しいバージョンがあればメニューと設定画面にダウンロードページへの案内を表示（今のバージョンは設定画面の下に表示）

## 💾 データの保存場所

| 実行方法 | 保存先 |
| --- | --- |
| Windows アプリ | `%APPDATA%\JustDoIt\` |
| macOS アプリ | `~/Library/Application Support/JustDoIt/` |
| ソースから実行 | `main.py` と同じフォルダ |

`log/work_log.csv`（作業ログ）と `config.json`（表示・タイマー・通知・週次レポートの設定）が保存されます。週次レポートに登録している場合は、まだ配信サービスに送れていない記録の追加・修正・削除が `log/report_queue.json` に一時的に保存されます。保存先はアプリの「設定」画面でも確認できます。

週次レポートに登録すると、レポート作成のために作業記録（日時・作業内容・時間）が配信サービスにも送信されます。サーバー上の記録は35日で自動削除され、配信停止時にはすぐ削除されます。記録一覧で記録を直す・消すと、配信サービス上の記録も同じように直ります。

新しいバージョンの確認では、GitHub の公開 API（最新リリースの情報）にアクセスするだけで、記録や設定などの情報は送りません。

## 🛠️ 開発者向け

### 週次レポート配信サービスのデプロイ（開発者が1回だけ行う）
利用者がメールアドレスを登録するだけで済むよう、配信用の GAS を開発者が1つだけ用意します。

1. **配信サービス専用の Google アカウント**で、Googleスプレッドシートを新規作成し、**「拡張機能」→「Apps Script」** を開く
   - メールはこのアカウントから送られる（利用者に差出人アドレスが見える）ため、普段使いのアカウントは使わない
   - 複数アカウントに同時ログインしていると Apps Script が開けないことがあるので、シークレットウィンドウなどで専用アカウントだけにログインして作業する
2. [`gas/report_service/Code.js`](gas/report_service/Code.js) を貼り付ける。プロジェクトの設定で「appsscript.json をエディタで表示」をオンにし、[`appsscript.json`](gas/report_service/appsscript.json) の内容も貼り付ける（タイムゾーン: Asia/Tokyo）
3. **「デプロイ」→「新しいデプロイ」→「ウェブアプリ」**、次のユーザーとして実行「自分」、アクセスできるユーザー「全員」でデプロイ
4. エディタで `createReportTrigger` を1回実行し、権限を承認する（1時間ごとに `sendDueReports` が実行され、届ける時刻を過ぎた利用者にだけレポートを送る）
5. 発行された URL を [`justdoit/report_service.py`](justdoit/report_service.py) の `REPORT_SERVICE_URL` に設定してビルドする（開発中は環境変数 `JUSTDOIT_REPORT_URL` でも指定可）

> ⚠️ `Code.js` を修正したら「デプロイ」→「デプロイを管理」→ 編集（鉛筆）→ バージョン「新バージョン」でデプロイし直さないと反映されません（URL は変わりません）。「新しいデプロイ」にすると URL が変わり、配布済みのアプリから記録が届かなくなるので注意してください。
>
> 「毎週月曜 9時」に送っていた以前のバージョンから更新した場合は、デプロイし直したあとに `createReportTrigger` を1回実行してください（古いトリガーが削除され、1時間ごとのトリガーに置き換わります）。

- 書き込みにはメール認証で発行した端末ごとのトークンが必要です（サーバーにはハッシュのみ保存）。URL が公開されても、他人の記録の読み書きはできません
- 確認コードの送信は、同じアドレスに対して1分に1回・6時間で5回まで、サービス全体でも1時間に15通までに制限し、レポート用の送信枠を残すようにしています（宛先を変えながら登録を繰り返されても、送信枠を使い切られないように）。確認コードは推測されにくい乱数（UUID）から作ります
- テストメールは、1人につき10分に1回・1日3回までです
- 無料の Google アカウントでは、メール送信は1日100通程度までです。利用者が増えたら Google Workspace への切り替えや、外部のメール配信サービスへの移行を検討してください

### ソースから実行
```bash
pip install -r requirements.txt
python main.py
```

### テスト
```bash
python -m unittest discover -s tests -v
```
画面の配色のテスト（`tests/test_theme.py` の一部）は Tkinter のウィンドウを作るため、画面（ディスプレイ）のない環境では自動でスキップされます。GitHub Actions では仮想ディスプレイ（Xvfb）の上で動かすので、配色のテストも毎回実行されます。

### アプリのビルド
```bash
pip install -r requirements-dev.txt
pyinstaller --noconfirm JustDoIt.spec
```
`dist/` に Windows なら `JustDoIt/JustDoIt.exe`、macOS なら `JustDoIt.app` が生成されます（各 OS 上でビルドする必要があります）。
ダウンロードを軽くするため、[`JustDoIt.spec`](JustDoIt.spec) で使わないライブラリ（scipy など）や画像形式のプラグイン、matplotlib のフォントを同梱しないようにしています。

### リリース
1. [`justdoit/__init__.py`](justdoit/__init__.py) の `__version__` を、次に出すバージョン（例: `1.2.0`）にしてコミット・push する
2. GitHub の **Releases →「Draft a new release」** で、同じ番号のタグ（例: `v1.2.0`）を新しく作って公開する

GitHub Actions（[`.github/workflows/build.yml`](.github/workflows/build.yml)）がテスト → Windows / macOS 両方のビルド → Release への添付まで自動で行います（タグを push しても同じように動きます）。タグと `__version__` が違う場合は、テストの段階で止まります（アプリに表示するバージョンや、新しいバージョンのお知らせがずれないように）。

## 🧩 工夫した点・苦労した点

- **作業の邪魔をしない UI**：画面ごとに目立つボタンを1つに絞り、確認ダイアログを極力なくした。タイマー終了時はウィンドウを最前面（`-topmost`）に出し、そのまま作業内容を入力できる。確認は「途中で閉じる」「記録を消す」のように取り返しがつかない操作のときだけ出す
- **追加ライブラリなしの OS 通知**：Windows では PowerShell からトースト通知を、macOS では `osascript` から通知センターを呼び出す。通知・音・前面表示は利用者が組み合わせを選べ、どれかが使えない環境でもアプリは止まらない
- **Windows / macOS で同じ見た目**：macOS では `tk.Button` の背景色が反映されないため、Label ベースのボタンを自作。フォントも OS ごとに切り替え。マウスを乗せたときは指の形のカーソル（Mac では不自然に見える）にせず、ボタンの色を変えて押せることを示す
- **Tkinter で角丸・リングをなめらかに**：Tkinter の Canvas は縁がギザギザになるため、角丸ボタンや進捗リングは Pillow で4倍の大きさに描いてから縮小した画像で表示（半透明の縁は Tk でうまく混ざらないので、背景色ごと描いた不透明な画像にする）
- **ライト / ダークの切り替え**：色は各画面に直接書かず、すべて1つの配色オブジェクトから読む作りにし、配色を入れ替えて画面を作り直すだけで切り替わるようにした。`ttk` の部品（選択欄・表）は色を変えられる `clam` テーマで配色に合わせる。`clam` に最初から決まっている状態ごとの色（フォーカス中は白い文字など）が残ると、ライトモードで白い背景に白い文字になって読めなくなる不具合があったため、状態ごとの色をすべて指定し直し、ライト・ダーク両方で文字と背景のコントラスト比（WCAG の基準）をテストで確かめるようにした
- **画面遷移とタイマーの整合性**：`after()` の予約IDを保持し、画面を切り替えるたびにキャンセルすることで、裏でタイマーが動き続ける不具合を解消
- **通信で UI を止めない**：記録の送信も、登録・配信停止の通信も別スレッド＋タイムアウト付きで行い、ネットワークが遅くてもアプリが固まらない。Tkinter は別スレッドから操作できないため、通信結果はキュー経由で画面のスレッドに渡す
- **記録を失わない**：作業ログを Excel で開いたままにしているなどで保存に失敗しても、入力した内容を残したまま画面にとどまり、閉じてから保存し直せる
- **読みやすい構成**：画面を持たない処理（設定・集計・配信サービスとの通信）と Tkinter の画面を別のモジュールに分け、画面を持たない処理を単体テストで確認できるようにした。画面は1画面1ファイルにし、画面の切り替えは `app.py` に集約
- **ダウンロードを軽く**：PyInstaller の設定ファイルで、開発環境に入っているだけの不要なライブラリや画像形式のプラグイン、matplotlib のフォントを同梱しないようにし、Windows 版の zip を約17%小さくした
- **GAS のハマりどころ**：`doGet` 未定義によるエラーや、コード修正後に再デプロイしないと古い版が動き続ける問題、複数アカウントでのログイン時に Apps Script が開けない問題を調査・解決
- **利用者に設定させない週次レポート**：当初は利用者が自分で GAS をデプロイする必要があったため、開発者が共用の配信サービスを持つ設計に変更。メールアドレスと確認コードだけで登録でき、アプリを開かなくても毎週レポートが届くことで習慣化を後押しする。トークン認証、確認コードの送信回数制限、メールソフトのリンク先読みで勝手に停止されないための確認ボタン、送信できなかった記録の再送キュー（記録の内容から作ったIDで、再送しても二重に保存されない。記録の修正・削除も同じキューで送るので、オフライン中に直しても順番どおりに反映される）など、公開サービスとして安全に運用できるようにした
- **利用者ごとに選べる配信タイミング**：利用者ごとに GAS のトリガーを作ると数の上限（1プロジェクト20本程度）にすぐ当たるため、1時間ごとのトリガー1本で「次に届ける日時」を過ぎた利用者にだけ送る設計にした。送信の遅れや失敗は次の回で再送し、タイミングを変えた直後に同じ週のレポートが2通届かないよう、前回から6日以上空ける
- **配布を見据えた設計**：ビルド後のアプリ内には書き込めないため、OS 標準のユーザーデータフォルダに保存先を切り替え。認証トークンなどの個人設定はリポジトリに含めない

## 🛠️ 技術スタック

- **言語**: Python 3.10+
- **GUI**: Tkinter（角丸ボタン・進捗リングの描画に Pillow）
- **データ処理・可視化**: pandas, Matplotlib
- **クラウド**: Google Apps Script（配信サービス）, Googleスプレッドシート（データ保存）, Gmail（メール送信）
- **配布**: PyInstaller, GitHub Actions
